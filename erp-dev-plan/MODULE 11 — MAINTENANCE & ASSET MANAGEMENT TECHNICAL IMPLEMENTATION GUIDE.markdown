# MODULE 11 — MAINTENANCE & ASSET MANAGEMENT TECHNICAL IMPLEMENTATION GUIDE

## 1. PURPOSE
The Maintenance & Asset Management Module structures the registration, valuation, preventive maintenance scheduling, and reactive work order tracking for the hotel's physical inventory, buildings, rooms, and shared hardware assets.

The module integrates with:
- Front Office (blocking room inventories when rooms go into out-of-order maintenance)
- Housekeeping (collecting room defect reports generated by attendants)
- Inventory & Stores (tracking maintenance spare parts and tool stock usage)

## 2. FUNCTIONAL REQUIREMENTS
The module shall allow authorized users to:
- Establish a master Asset Register detailing purchasing values, depreciations, and locations.
- Log incoming maintenance and repair tickets.
- Dispatch Maintenance Work Orders to designated technicians.
- Schedule recurring Preventative Maintenance tasks for HVAC, generator, and water systems.
- Monitor spares and materials consumption on individual work orders.
- Block rooms for Maintenance, automatically triggering inventory releases in the PMS.

## 3. MAINTENANCE WORK ORDER STATE MACHINE
```
Defect Reported ➔ Ticket Created ➔ Work Order Dispatched ➔ In-Progress ➔ Parts Assigned 
  ➔ Repair Completed ➔ Inspection Passed ➔ Work Order Closed ➔ Asset/Room Restored
```

## 4. DATABASE DESIGN
### AssetMaster
- `AssetID` (PK, UUID)
- `AssetCode` (String, Unique, e.g., AST-GEN-002)
- `Name` (String)
- `CategoryID` (FK)
- `PurchaseDate` (Date)
- `PurchaseCost` (Decimal)
- `CurrentValue` (Decimal)
- `DepreciationRate` (Decimal)
- `LocationDescription` (String)
- `IsActive` (Boolean)

### MaintenanceTicket
- `TicketID` (PK, UUID)
- `TicketNumber` (Unique, e.g., TKT-2026-0034)
- `ReporterUserID` (FK to User)
- `RoomID` (FK, Optional)
- `AssetID` (FK, Optional)
- `Description` (Text)
- `Priority` (Enum: LOW, MEDIUM, HIGH, EMERGENCY)
- `Status` (Enum: OPEN, DEFERRED, IN_PROGRESS, RESOLVED, CANCELLED)
- `CreatedAt` (Timestamp)

### WorkOrder
- `WorkOrderID` (PK, UUID)
- `WONumber` (Unique, e.g., WO-2026-0041)
- `TicketID` (FK)
- `TechnicianUserID` (FK to User)
- `ScheduledDate` (Date)
- `CompletionDate` (Date, Nullable)
- `Status` (Enum: ASSIGNED, IN_PROGRESS, COMPLETED, ON_HOLD)
- `LaboursHour` (Decimal, Nullable)
- `PartsCost` (Decimal, Default: 0)
- `Notes` (Text, Nullable)

### WorkOrderPart
- `WorkOrderPartID` (PK, UUID)
- `WorkOrderID` (FK)
- `ItemID` (FK, links to Inventory)
- `QuantityUsed` (Decimal)
- `UnitPrice` (Decimal)

## 5. BUSINESS RULES
1. Room Status Locks: When a `MaintenanceTicket` with a status of `EMERGENCY` is linked to a physical `RoomID`, the system must programmatically update the room state to `OUT_OF_ORDER` and block bookings.
2. Spares Deduction: Consuming parts on a work order must write to the `StockTransaction` ledger in the Inventory Module, deducting quantities from the maintenance store.
3. Overdue Priority Alerts: Any ticket marked as `EMERGENCY` that remains in an `OPEN` state for more than 30 minutes must trigger an automated escalation email and SMS to the Maintenance Manager.

## 6. USER INTERFACE
### Maintenance Dispatch Panel
- Real-time priority board displaying outstanding tickets sorted by urgency.
- Drag-and-drop tool: Drag tickets to technicians to generate a `WorkOrder`.
- Live status tracker of hotel rooms indicating room repair holds.

### Technician Mobile Log (Mobile Web View)
- Work order queue assigned to the active technician.
- Input triggers to start and stop job timers, capture notes, and request parts from inventory.

## 7. SUGGESTED API ENDPOINTS
- `POST /api/maintenance/tickets`
- `GET /api/maintenance/tickets/pending`
- `POST /api/maintenance/work-orders`
- `POST /api/maintenance/work-orders/{id}/parts`
- `PUT /api/maintenance/work-orders/{id}/complete`

## 8. SECURITY AND ACCESS CONTROL
- **Technician**: Permitted: View assigned work orders, update status to IN_PROGRESS, input labour hours, request parts. Denied: Create PM schedules, delete maintenance tickets, override room holds.
- **Maintenance Manager**: Permitted: All technician actions + dispatch work orders, configure preventative maintenance schedules, release OOO rooms, manage asset depreciation tables.

## 9. AUDIT LOG SPECIFICATION
Log: `MAINTENANCE_TICKET_CREATED`, `WORK_ORDER_DISPATCHED`, `ROOM_OUT_OF_ORDER_TRIGGERED`, `WORK_ORDER_COMPLETED`.

## 10. KEY DESIGN PRINCIPLE
Minimized asset downtime. Building a proactive maintenance loop ensures room inventory is optimized and building issues are quickly logged and resolved.\n
